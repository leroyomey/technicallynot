---
name: fix-odds
description: Every issue, bug or problem an agent lists (in replies and on the report's Found / Blockers / Remains lines) gets a one-sentence fix and an honest percentage chance that the fix solves it.
for: every-agent
tnai-hidden: true
---
- Whenever you list issues, bugs, problems or limitations (in a reply, a table, or on the Technically Not report's "- Found:", "- Blockers:" and "- Remains:" lines; the report's "- Untested:" items are not problems and take no fix percentage), put next to each one a proposed fix in one short sentence and the chance, 0–100%, that this fix fully solves that issue. In a reply every listed issue ends with "Fix: <one sentence> (NN%)", the percentage included every time. Never put a list of issues in a table (in a terminal a table breaks or changes shape when the view gets narrower, lines re-wrap at any width): write numbered lines, or for longer items numbered blocks as in the outcomes rule below, with "- Fix: <one sentence> (NN%)" as a line of the block. On a report line write each item as "<issue> → fix: <one sentence> (fix NN%)" and never use "; " inside an item, since items are split on it. The "(fix NN%)" is always the item's last text and holds only the number; any reason goes before it, e.g. "- Found: empty list crashes avg → fix: start the sum at 0, only matters for huge lists (fix 90%)". This applies on every model and every task, even a short one.
- Rate the chance honestly: lower it for anything you have not confirmed (untested CLI or API behavior, an unknown cause, a fix outside this project's control), mark such fixes "(check first)", and when a number is low, say why in a few words. Don't inflate it to please the user. A fix that only explains or works around the issue scores low; a verified cause with a proven fix scores high.
- Show the same list again with outcomes: when you report on a list of issues or fixes you gave earlier in this conversation (after working on it, or when the user asks where it stands), repeat that list as numbered blocks, never as a table, with the same numbers and order and one count line above it ("8 issues: 6 fixed, 2 partly"). A block is a bold line "N · <issue>", then one list line each: "- Outcome: <word>", "- How we know: <text>" and, unless it is Fixed, "- Fix: <one sentence> (NN%)"; a blank line between blocks. The Outcome line holds exactly one of four words and nothing else after the label (Technically Not colors the word only when it stands alone): "Fixed" (done and a check proves it), "Partly", "Still failing" (tried and it did not work) or "Not started". "How we know" names the check or what you saw, and "not checked" when there is none; for Partly it also says what is left, for Still failing what was tried, for Not started who has it if someone does. A block without proof is never "Fixed". Never say "all fixed" in a sentence when a block is Partly, Still failing or Not started.
- Skip the fix only for an issue you already fixed in this task (say it is fixed) or when there is truly no fix yet (write "Fix: none known yet (0%)" and what would find one). Items that are not problems (finished work on "- Did:", plain facts) get no fix or percentage.
