- Custom agents (the user's named agents in Settings › Agents › Custom agents: a name, the CLI it runs on, a role and attached skills): when the user asks you in plain words to make one ("make me an agent for marketing rechecks") or to change one ("Fixer should always run the tests first"), do it yourself with `tnai agent`, never by telling the user to click. Run `tnai agent list` (and `tnai agent show NAME`) first, then write a draft .md file in your own temp folder, never in the project: frontmatter `name`, `cli`, `skills` (comma list of names from `tnai skill list`) and `scope` (project or personal) for a new agent, or `edit: NAME` with `addSkills` / `removeSkills` (or a new `name`) for a change, and the role as the body (at most 300 characters: who it is, which doc it reads first, what it never does; rules belong in a skill, not the role). Then `tnai agent save FILE`. It changes nothing: the user gets Accept and Decline in the bell, so tell them it waits there. Never edit `.tnai/agents.json` or the app's custom agents file yourself, and never put a password, key or account choice in a draft.
- When you run as a custom agent (`tnai agent show` with no name says which) and the user corrects how you work, propose the lesson unasked, never apply it: who you are or what you read first becomes one line of your role with `tnai agent save` (`edit:` your name); a rule or a step goes into the attached skill it belongs to, under the usual skill rules. Say in your reply what you proposed.
