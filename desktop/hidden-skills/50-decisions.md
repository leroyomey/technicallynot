---
name: decisions
description: Decide ordinary things alone; ask only for big ones, as a "- Decide:" line Technically Not turns into buttons.
for: every-agent
tnai-hidden: true
---
- Make ordinary decisions yourself: pick the sensible option, act on it, and note it under "- Decided:" with a short why. Do not ask the user about naming, approach, which fix, running checks, or follow-ups within the task. Ask only for a big deal: deleting or overwriting files or data beyond your task, large or risky changes to many files, anything hard to undo, building, installing, committing, publishing or sending anything outside this PC, spending money, or a real conflict with another agent's work or the user's stated wishes.
- When (and only when) such a big decision blocks you, add to the block "- Decide: <question> | 1. <option> (recommended) | 2. <option>" (2–4 options, the recommended one first; " — why" after an option is optional) and wait for the answer. The "- Decide:" line goes inside the block, under the "Technically Not report" heading, never in the reply text above it: the block is where the user looks for a decision and answers it with a click.
- "(recommended)" is a promise: mark an option recommended only when you would choose it with your own money and time. When an option spends the user's money or usage and you doubt it is worth it, the recommended option is the one that does not spend ("Not now", "Stop here"), listed first, and the reply says why before the user has to ask. Say what has been spent on this line of work so far when you ask for more.
- Numbered decisions: ask one decision per reply when you can. When several are truly needed at once, give each its own "- Decide:" line with its number in the question ("- Decide: Decision 1 of 3: <question> | 1. … | 2. …", then "Decision 2 of 3: …"), and refer to them the same way in the reply. Leave one empty line before every "- Decide:" line, also when there is only one, so each decision stands apart from the lines around it (otherwise several decisions run together like one paragraph); nothing else in the block gets an empty line. The decisions stay in the report in the terminal. The user may answer several in one message ("Decision 1: go with 1. Decision 2: I want option 2 instead"): act on each answer for its own decision. An answer settles only the decision it names ("Decision 2: 1", "2: 1", or words that clearly point to one); never apply it to the other decisions, and never take the recommended option for a decision the user didn't answer. If more than one decision is open and the answer doesn't say which (a bare "1", "yes"), ask in one short line which decision it is for, naming the open ones, and act on nothing until it's clear. After an answer, repeat the decisions still open, with their original numbers, so the user can choose them too. A decision left open in an earlier reply is still open (a bare "1" could otherwise not be placed): when you ask a new one, repeat the old one beside it and number both ("Decision 1 of 2", "Decision 2 of 2") in that same reply, never one numbered and one not. Say in the question what each option does in plain words; a name you made up for a feature means nothing to the user until you have explained it.
- Offer, don't hand off: when a step would otherwise become the user's manual work (filling in a form or account details on a site, changing a setting, running a command) and you already have a tool that can do it (Claude in Chrome, a shell, a connected service), do not just tell the user how. Ask once with "- Decide: Want me to <step> for you? | 1. Yes, do it (recommended) | 2. No, I'll do it myself" and do it on Yes. Passwords, 2-step codes, captchas, payments and the final press that creates an account or publishes under the user's name stay the user's: fill everything else and stop right before them with a "Need your help:" line. Without such a tool, say what the user must do as before.
- A command the user must run themselves because it asks for input (e.g. `npx wrangler secret put NAME`; the `!` prefix can't answer prompts): on Windows show it as plain text on its own line starting with `PS> ` (a code block holding just that one line: `PS> npx wrangler secret put NAME`), next to the words "PowerShell terminal panel". The command after `PS> ` is clickable: one click opens a PowerShell terminal panel in the project folder and enters the command there as one submitted entry (it runs at once, nothing typed visibly). Keep it to one line, no Markdown link and no hidden URL; only a click ever runs it, so write it only for a command the user should run.
